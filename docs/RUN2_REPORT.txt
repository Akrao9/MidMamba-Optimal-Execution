MidMamba PPO Run 2 Report
Created: 2026-05-14

Purpose
-------
This report records the second full Stable-Baselines3 PPO training experiment
for MidMamba. Run 2 changed the training geometry from 48 to 80 environments and
increased completion pressure in the reward. The run improved held-out March
implementation shortfall, but failed the completion target.

Run 2 Goal
----------
Primary goal:
  Reduce the leftover inventory problem observed in Run 1 while preserving or
  improving the held-out March implementation-shortfall edge versus TWAP.

Run 1 issue being addressed:
  Run 1 had good March IS versus TWAP, but left about 5.9 pct of the parent
  order unfilled on average.

Interpretation
--------------
Run 2 is not a clean improvement over Run 1. It improved held-out March
implementation shortfall, but it worsened completion materially.

Positive signs:
  - Mean March IS improved versus Run 1.
  - Paired policy advantage versus TWAP improved from about -1.011 bps to
    about -1.202 bps.
  - PPO training remained stable.
  - 80 environments worked without memory pressure and achieved about 1270 fps.

Main failure:
  The policy left too much inventory unfilled. Mean remaining inventory rose to
  about 11.6 pct of the 100,000 unit parent order.

Statistical caveat:
  The paired policy advantage versus TWAP is promising, but the 95 pct
  confidence interval still crosses zero. This is research-positive, not
  production-conclusive.

  Borderline / failed by strict greater-than rule. Observed 55.0 pct.

Conclusion
----------
Run 2 learned a stronger opportunistic execution signal, but the reward still
allows the policy to score well while leaving too much inventory. For portfolio
presentation, Run 2 is useful because it exposes a real execution-design tradeoff:
improved shortfall versus unacceptable completion risk.

Recommended Next Experiment
---------------------------
Do not focus on more environments or longer training first. The next issue is
reward and environment design.

Recommended reward settings:
  BETA_COMPLETION = 4.0
  TERMINAL_PENALTY_BPS = 500.0

Better structural fix:
  Add or enforce stronger final liquidation behavior so the policy cannot
  finish evaluation with more than 1 to 2 pct remaining inventory while still
  looking good on IS.

Suggested next acceptance criteria:
  filled_mean >= 99,000
  remaining_mean <= 1,000
  policy - TWAP <= 0 bps
  win_rate_vs_twap >= 55 pct

Portfolio Framing
-----------------
Run 2 should be described honestly:
  The agent improved mean held-out March implementation shortfall versus TWAP,
  but did so by accepting materially higher under-completion. This motivated the
  next iteration toward stricter inventory-completion constraints.
