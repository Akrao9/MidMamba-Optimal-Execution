MidMamba PPO Run 3 Report
Created: 2026-05-15

Purpose
-------
This report records the third full Stable-Baselines3 PPO training experiment
for MidMamba. Run 3 was the first full run after correcting the execution
accounting issue discovered in Run 2.

Run 3 focused on completion discipline:
  - The final step was changed to attempt marketable liquidation of all
    remaining visible inventory.
  - Terminal and completion penalties were changed so they are not clipped away
    by REWARD_CLIP.
  - Evaluation was changed to report IS+opp, which marks leftover inventory to
    the final mid price.

The result is a cleaner execution policy with much better completion, but it
does not yet outperform TWAP on the corrected March held-out metric.

Run 3 Goal
----------
Primary goal:
  Fix the incomplete-execution problem from Run 2 while keeping the policy
  competitive versus TWAP on held-out March 2025 data.

Run 2 problem being addressed:
  Run 2 had apparently strong raw implementation shortfall, but after corrected
  opportunity-cost accounting it left too much inventory unfinished.

Corrected Run 2 reference:
  Policy raw IS:   -1.0325 bps
  Policy IS+opp:  +0.5454 bps
  Mean filled:    88,361
  Mean remaining: 11,638.9071

Accounting Fixes Before Run
---------------------------
Final liquidation:
  On the final environment step, the policy must attempt to execute all
  remaining visible inventory with a marketable action.

Reward clipping:
  REWARD_CLIP applies only to the shaped IS/schedule reward component.
  Completion and terminal penalties bypass the clip.

Corrected evaluation metric:
  IS+opp = realized implementation shortfall plus opportunity shortfall from
  remaining inventory marked to the final mid price.

Why this matters:
  Raw IS can look good when the policy avoids trading difficult inventory.
  IS+opp penalizes that behavior and is the headline metric used for this run.

Interpretation
--------------
Run 3 is a successful accounting and completion fix, but not a profitable or
outperforming execution policy on held-out March data.

Positive signs:
  - The policy no longer wins by leaving large inventory unfinished.
  - Mean remaining inventory fell from about 11.6 pct in corrected Run 2 to
    about 1.3 pct in Run 3.
  - The raw IS and corrected IS+opp metrics are now close, which means the
    reported execution quality is no longer dominated by hidden leftover
    inventory.
  - PPO training was stable with 96 environments and reached about 1287 fps.
  - The validation curve improved strongly under the stricter reward.

Main failure:
  On March held-out data, the policy underperformed TWAP on corrected IS+opp by
  about +0.720 bps and had a 48.0 pct win rate versus TWAP.

Statistical caveat:
  The paired difference versus TWAP has a 95 pct CI halfwidth of about 2.027
  bps, so the policy is not statistically proven worse either. The honest
  conclusion is no reliable held-out edge.

Portfolio Framing
-----------------
Run 3 should be presented as an important negative/diagnostic result:

  After correcting the inventory accounting, the agent learned to complete the
  order much more reliably. However, once evaluated with opportunity cost for
  residual inventory, the best validation checkpoint did not outperform TWAP on
  the March held-out set.

This is valuable for a portfolio project because it demonstrates:
  - Proper train / validation / test separation.
  - Recognition and correction of a reward-accounting loophole.
  - Paired baseline evaluation.
  - Honest reporting when a model does not beat a simple benchmark.

Recommended Next Experiment
---------------------------
Do not continue this exact run. The learning rate was nearly exhausted and the
best checkpoint had already been selected.

Recommended Run 4 direction:
  Keep the completion fixes and strong terminal accounting, but reduce schedule
  pressure so the policy has more freedom to use passive or opportunistic fills
  while still being forced to finish.

Suggested settings:
  NUM_ENVS = 96
  ROLLOUT_STEPS = 512

Run 4 acceptance criteria:

  remaining_mean <= 1,000
  policy IS+opp <= TWAP IS+opp
  paired policy - TWAP <= 0 bps
  win_rate_vs_twap >= 55 pct

Conclusion
----------
Run 3 fixed the major completion-accounting flaw from Run 2 and produced a
substantially more honest execution policy. It did not beat TWAP on the
corrected March held-out test, so it should not be described as profitable.
The next experiment should focus on recovering shortfall edge without reopening
the incomplete-execution loophole.
