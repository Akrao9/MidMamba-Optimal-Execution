MidMamba PPO Run 4 Report
Created: 2026-05-15

Purpose
-------
This report records the fourth full Stable-Baselines3 PPO training experiment
for MidMamba. Run 4 was a focused ablation after Run 3 fixed the incomplete
execution accounting problem but still underperformed TWAP on the corrected
March held-out metric.

Run 4 changed two things:
  - BETA_SCHEDULE was reduced from 0.1 to 0.03.
  - USE_NUMBA was set to False after the NumPy simulator path proved faster in
    this SubprocVecEnv setup.

The goal was to preserve the strong completion discipline from Run 3 while
allowing the policy more freedom to deviate from TWAP when the book state was
favorable.

Run 4 Goal
----------
Primary goal:
  Recover implementation-shortfall edge without reopening the incomplete-
  execution loophole.

Run 3 problem being addressed:
  Run 3 completed much more reliably, but underperformed TWAP on corrected
  March IS+opp by about +0.720 bps.

Run 3 reference:
  Policy raw IS:   +0.7729 bps
  Policy IS+opp:  +0.8916 bps
  Mean filled:    98,695
  Mean remaining: 1,304.5602
  Policy - TWAP:  +0.720 bps on corrected IS+opp

Accounting / Evaluation Metric
------------------------------
Headline metric:
  Corrected IS+opp.

Definition:
  IS+opp = realized implementation shortfall plus opportunity shortfall from
  remaining inventory marked to the final mid price.

Reason:
  Raw IS can reward a policy for not trading difficult residual inventory.
  IS+opp penalizes that behavior and is the metric used for Run 4 conclusions.

Interpretation
--------------
Run 4 is the best corrected run by March IS+opp, but it still does not produce
a robust held-out edge versus TWAP.

Positive signs:
  - Best validation reward improved from Run 3's -1.88 to Run 4's +1.88.
  - March corrected IS+opp improved from +0.8916 bps to +0.7091 bps.
  - The policy completed most orders and did not rely on hiding leftover
    inventory.
  - Strong localized outperformance appeared on 2025-03-03 and 2025-03-04, and
    on selected later March days.

Main failure:
  Month-wide March performance remained worse than TWAP by about +0.537 bps on
  corrected IS+opp.

Statistical caveat:
  The policy's standard deviation was much higher than TWAP's. With only 200
  evaluation windows, the mean difference is noisy. The result should be read as
  no reliable edge, not as definitive proof that the policy can never beat TWAP.

Final Project Conclusion
------------------------
The final static policy did not beat TWAP over the full held-out March month.
However, the daily breakdown shows strong early-March performance and mixed
later performance. This suggests the learned execution policy is regime-
sensitive and may decay as the market moves away from the validation period.

Recommended Future Direction
----------------------------
Do not continue simple single-month static retraining runs without new data.
The next scientifically useful step is walk-forward retraining:

  Train on a recent rolling window.
  Validate on the latest few sessions.
  Test/deploy on the next one to five sessions.
  Slide forward and repeat.

If April data is available:
  Train on January, February, and early March.
  Validate on later March.
  Test on April.

If April data is not available:
  Wrap the project as a rigorous negative/diagnostic RL execution study.

Portfolio Framing
-----------------
Run 4 should be presented as the final best corrected policy:

  The policy learned meaningful execution behavior and showed localized
  outperformance, especially on the first two March test sessions. But a single
  static model did not maintain a robust month-wide advantage versus TWAP. The
  project therefore motivates rolling walk-forward retraining and regime
  monitoring rather than claiming a profitable static execution agent.

Conclusion
----------
Run 4 improved over Run 3 and is the best corrected model in the project, but it
still failed the main held-out benchmark. The project should be wrapped as a
complete and honest RL execution research project: strong simulator and training
infrastructure, corrected accounting, paired baseline evaluation, clear evidence
of regime sensitivity, and no overstated profitability claim.
